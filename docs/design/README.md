# Portman Windows 首版设计

> 状态：Draft v0.2  
> 日期：2026-08-20  
> 技术栈：Tauri 2、Rust、Vite、pnpm、TypeScript、React

## 1. 项目定位

Portman 是一个以“服务”为中心的本机端口管理工具。它不展示一张需要用户自行理解的连接表，而是维护一组用户关注的服务，并持续回答：

- 服务是否正在监听；
- 服务的内部端口和对外端口是什么；
- 端口转发是否期望启用、是否实际生效；
- 服务由哪个进程或 WSL 发行版提供；
- 当前异常是服务停止、端口被抢占、权限不足，还是转发配置漂移。

Windows 是首个交付平台。首版支持 Windows 原生进程和 WSL 服务，配置保存在 `%USERPROFILE%\.portman\config.yaml`。

## 2. 首版范围

### 2.1 必须实现

1. 服务看板
   - 展示关注服务的运行状态、内部端点、外部端点、转发状态、详情和类别。
   - 类别为 `windows` 或 `wsl`。
   - 支持手动刷新，并在窗口可见时周期刷新。
2. 添加关注服务
   - 枚举当前已绑定、正在监听且尚未关注的端口。
   - Windows 来源包含 TCP/UDP、IPv4/IPv6；WSL 来源按发行版枚举。
   - 用户从候选列表选择后创建关注项，而不是手填一个无法验证的端口。
3. 端口转发
   - 为 TCP 服务新增一条转发规则。
   - 启用、禁用、删除转发规则。
   - 显示配置期望状态与 Windows 实际状态的差异。
4. 取消关注
   - 删除服务前，如存在转发，明确提示处理方式。
   - 默认先删除 Portman 管理的系统转发，再删除关注项，避免遗留规则。
5. 本地配置
   - YAML 配置版本化、校验、原子写入并保留最近一次备份。

### 2.2 明确不在首版

- 启动、停止或重启业务进程；
- 结束占用端口的进程；
- UDP 端口转发；
- SSH、NAT、Hyper-V 防火墙等多种转发后端；
- 自动修改 Windows Defender Firewall；
- 远程主机管理、账号体系和云同步；
- macOS/Linux 桌面版本。

Windows PortProxy 只提供 TCP 转发，因此 UDP 服务可以关注和查看，但转发操作不可用。首版覆盖 `v4tov4`、`v4tov6`、`v6tov4`、`v6tov6` 四种 TCP 代理类型。监听 `0.0.0.0` 或 `::` 也不等于其他机器一定可访问，Windows 防火墙仍可能阻断连接；首版只给出诊断提示，不擅自放行防火墙。

## 3. 核心概念

### 3.1 发现项、关注服务和运行快照

- **发现项（Discovered Endpoint）**：一次扫描得到的实时监听端点，短生命周期，不写入配置。
- **关注服务（Tracked Service）**：用户选择后写入配置的稳定对象，表达“我关心谁”。
- **运行快照（Runtime Snapshot）**：当前扫描结果与配置匹配后的派生状态，不写入配置。
- **转发规则（Forwarding）**：Portman 管理的一条 Windows 端口代理规则；一个服务首版最多一条。

将配置与实时状态分离，可以避免把 PID、WSL IP、最近错误等易变数据写回 YAML，也能正确表达“配置为启用，但系统规则已被外部删除”的漂移状态。

### 3.2 端口定义

- **内部端点**：业务服务真实监听的位置，如 `127.0.0.1:5173` 或 WSL 中的 `0.0.0.0:3000`。
- **外部端点**：Windows `portproxy` 的监听位置，如 `127.0.0.1:13000` 或 `0.0.0.0:13000`。
- **转发目标**：Windows 服务通常为可连接的本机地址；WSL 服务为当前发行版 IP 与内部端口。

外部监听地址默认 `127.0.0.1`。用户可选择 IPv4/IPv6 loopback 或通配地址；显式选择 `0.0.0.0`/`::` 时，界面提示这会扩大局域网暴露面，且可能仍需配置防火墙。

## 4. 用户流程

### 4.1 看板

每个服务卡片/表格行显示：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 名称 | Web Admin | 用户可读名称 |
| 类别 | WSL / Ubuntu | Windows 显示进程，WSL 显示发行版 |
| 服务状态 | 运行中 | 运行中、已停止、冲突、未知 |
| 内部端点 | `0.0.0.0:5173/TCP` | 真实监听端点 |
| 外部端点 | `127.0.0.1:15173` | 未配置时显示“未配置” |
| 转发状态 | 已生效 | 未配置、已禁用、已生效、待修复、冲突、错误 |
| 详情 | node.exe / PID 1234 | 路径、PID、WSL 发行版、最近诊断 |

状态优先级为：配置/扫描错误 > 端口冲突 > 转发漂移 > 服务停止 > 正常。列表顶部提供搜索和 `全部 / Windows / WSL / 异常` 筛选。

### 4.2 添加服务

1. 点击“添加服务”，主内容区进入添加页面，不弹出模态框。
2. 后端重新扫描 Windows 与 WSL 监听端口。
3. 排除已关注端口，按 Windows 端口或 WSL 发行版与端口合并候选。
4. 用户直接选择端口；同号的不同地址和协议绑定合并，默认隐藏纯 UDP 项，列表严格按端口号排序。
5. 用户确认默认名称，后端再次验证该端口的全部候选仍存在，然后将多个绑定原子写入一个服务配置。
6. 返回看板并刷新快照。

候选在扫描后可能消失，因此“加入关注”必须二次验证。若端口已停止，提示用户刷新后重试，不能创建幽灵服务。

### 4.3 管理转发

新增时输入外部端口和监听范围。后端依次执行参数校验、冲突检测、目标解析、UAC 操作和结果复核。只有系统规则创建成功后才提交配置；若配置写入失败，则尝试回滚刚创建的系统规则，并向用户报告回滚结果。

禁用会删除系统 `portproxy` 规则，但保留转发配置及 `enabled: false`，以后可再次启用。删除会删除系统规则并从服务配置移除 `forwarding`。

### 4.4 取消关注

- 无转发：确认后直接删除关注项。
- 有已禁用转发：删除转发配置和关注项。
- 有期望启用的转发：默认执行“删除系统转发并取消关注”；若系统清理失败，不删除配置，避免不可见的遗留规则。

## 5. 验收标准

1. 新安装首次启动时自动创建配置目录和合法的空配置。
2. Windows TCP 监听端口能显示 PID、进程名和可获取的可执行路径。
3. WSL 已运行发行版中的监听端口可作为候选加入关注。
4. 已关注端点不重复出现在新增候选中。
5. 业务进程重启、PID 变化后，只要端口和身份匹配，服务仍显示运行中。
6. 同一端口被其他程序占用时显示冲突，而不是运行中。
7. TCP 转发新增、禁用、再启用、删除均经过 UAC 且能在操作后复核。
8. 外部删除或修改系统规则后，看板显示待修复/冲突。
9. WSL IP 变化后不会显示假正常，用户可以触发修复。
10. 配置写入中断不会产生半截 YAML；非法配置不会被静默覆盖。

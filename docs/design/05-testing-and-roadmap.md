# 测试、风险与迭代计划

## 1. 测试策略

### 1.1 Rust 单元测试

- IPv4/IPv6 地址和端口字节序转换；
- TCP 状态过滤；
- Windows 路径和监听地址规范化；
- `ss` 多种输出样例解析；
- 四种 PortProxy 注册表键、值名和值数据解析；
- 非法注册表值产生 warning 而不是崩溃；
- IP Helper 状态查询和参数变更通知结果映射；
- 配置校验、未知版本拒绝和 v1 round-trip；
- 服务身份强匹配、弱匹配、冲突判定；
- 转发状态矩阵；
- 系统成功/配置失败时的补偿路径。

所有外部依赖通过 trait 注入：`PortScanner`、`WslAdapter`、`PortProxyAdapter`、`ConfigRepository`、`ElevationRunner`。应用层测试使用 fake，不要求 UAC。

### 1.2 Windows 集成测试

- 启动临时 TCP IPv4/IPv6 listener，确认能发现当前 PID；
- 启动 UDP socket，确认能发现绑定；
- 关闭并重新启动进程，验证 PID 变化不影响匹配；
- 用另一可执行文件占用同端口，验证 conflict；
- 在测试发行版内启动 listener，验证 WSL 发现；
- 管理员测试任务中新增临时高位端口转发、复核、删除；
- 模拟 WSL IP/目标变化，验证 repair_required 与修复。

测试创建的所有系统规则使用预留高位端口并在 `finally`/drop guard 中清理。若清理失败，测试必须打印精确监听键，不能留下无名规则。

### 1.3 前端测试

- 状态徽标和 capability 对操作按钮的控制；
- 候选搜索、筛选、重复项排除；
- UAC 取消、部分扫描 warning 和数据陈旧状态；
- 删除服务的不同确认文案；
- 转发冲突、漂移和修复流程。

### 1.4 端到端验收

至少在 Windows 10、Windows 11 上验证普通用户启动；WSL 覆盖一个 WSL2 发行版。E2E 测试不得假定固定 WSL IP 或固定语言环境。

## 2. 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 注册表存在外部或损坏规则 | 误删第三方规则或解析崩溃 | 精确键匹配、坏值 warning、删除前比较完整目标 |
| IP Helper 未运行或通知失败 | 注册表正确但转发不生效 | 显示服务状态、显式启动操作、变更后发送通知并复核 |
| WSL IP 重启后变化 | 转发指向旧地址 | 配置保存发行版身份、只读漂移检测、显式修复 |
| 系统规则与 YAML 双写 | 一边成功一边失败 | 串行操作、复核、原子写和补偿事务 |
| 端口被其他进程抢占 | 错把陌生进程视作服务 | 不使用 PID，使用端口加身份匹配并显示 conflict |
| UAC 被取消 | 操作中断 | 主进程普通权限，取消作为可恢复业务结果 |
| 监听所有网卡带来暴露 | 安全风险 | 默认 loopback，选择 `0.0.0.0` 时显式警告 |
| WSL 内缺少 `ss` | 无法发现 | 单发行版 warning；后续再评估可靠 fallback |
| 进程路径不可读取 | 身份匹配变弱 | 保留候选、标记弱匹配、使用进程名并提示 |

## 3. 实施阶段

### Phase 0：工程骨架

- 创建 Tauri 2 + Vite + React + TypeScript + pnpm 工程；
- 建立 Rust 分层、统一错误和日志；
- 建立 CI：格式、lint、Rust/前端测试和 Windows 构建。

### Phase 1：发现与关注

- Windows TCP/UDP 与进程信息扫描；
- WSL 发行版和 `ss` 扫描；
- YAML 仓储、服务 CRUD；
- 候选列表和服务看板；
- 状态匹配与部分失败 warning。

完成标志：不涉及管理员权限时，核心“发现—关注—查看—取消关注”闭环可用。

### Phase 2：端口转发

- 四类 PortProxy 注册表读取、冲突检测和状态聚合；
- IP Helper 状态、显式启动和参数变更通知；
- 提权 helper；
- 新增、启用、禁用、删除、修复；
- 补偿事务和操作后复核；
- WSL IP 漂移诊断。

### Phase 3：稳定性与交付

- Windows 10/11、中文/英文系统验证；
- 安装包、应用图标、签名策略；
- 配置损坏恢复指引、日志轮转和诊断导出；
- 性能与长时间运行测试。

## 4. 后续候选能力

- 由 Portman 管理且可审计的 Windows Firewall 规则；
- 单服务多转发规则和 UDP 转发后端；
- 开机自动修复 WSL 转发（需单独设计无交互权限模型）；
- 服务分组、标签、排序和导入导出；
- 托盘状态和异常通知；
- 跨平台 scanner/forwarder adapter。

## 5. 开发前仍需产品确认的默认项

这些项目不阻塞当前设计，可按推荐默认值实现，后续通过评审调整：

1. 外部监听默认值：推荐 `127.0.0.1`，而不是 `0.0.0.0`。
2. 代理类型默认值：`v4tov4`；其他地址族组合收纳在高级选项。
3. 删除关注项：推荐必须先成功清理其启用中的托管转发。
4. 自动刷新：首版关闭，只在启动、手动刷新及操作完成后扫描。
5. WSL 扫描范围：推荐只扫描运行中的发行版，避免扫描行为启动 WSL。
6. UDP：推荐允许关注和查看，但明确标记首版不可转发。

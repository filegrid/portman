# 产品与交互设计

## 1. 信息架构

首版保持单窗口、两层导航：

- **服务**：默认页，管理已关注服务及其转发。
- **设置**：配置刷新间隔、默认外部监听地址，查看配置目录和诊断信息。

“添加服务”以模态页或右侧抽屉打开，不增加独立导航。服务详情同样使用抽屉，避免离开看板上下文。

## 2. 服务状态

### 2.1 运行状态

| 状态 | 判定 | UI 语义 |
| --- | --- | --- |
| `running` | 找到内部端点且身份匹配 | 绿色“运行中” |
| `stopped` | 未找到内部端点 | 灰色“已停止” |
| `conflict` | 端口存在，但进程路径/WSL 发行版等身份不匹配 | 红色“端口被其他服务占用” |
| `unknown` | 扫描失败或权限不足，无法作出可靠判断 | 黄色“状态未知” |

Windows 进程的 PID 不是身份字段，因为重启后会变化。首版用协议、端口、地址范围和规范化可执行路径共同匹配。拿不到路径时退化为进程名，并在详情中标记“弱匹配”。WSL 使用发行版、协议和端口匹配；进程名只用于显示，不作为强制身份字段。

### 2.2 转发状态

| 状态 | 判定 |
| --- | --- |
| `unconfigured` | 服务无转发配置 |
| `disabled` | 配置存在且 `enabled: false`，系统中也无对应规则 |
| `active` | 期望启用，系统规则的监听端点和目标都一致 |
| `repair_required` | 期望启用，但规则缺失，或 WSL 当前 IP 与规则目标不同 |
| `conflict` | 外部端点被无关监听器或不同转发规则占用 |
| `error` | 无法读取系统规则或完成诊断 |

运行状态和转发状态分别展示。例如 WSL 服务停止时，已有 `portproxy` 规则仍可能监听，界面应显示“服务已停止 / 转发已配置”，不能合并为单个模糊的红绿灯。

## 3. 关键页面

### 3.1 空状态

首次启动显示简短说明和主按钮“添加服务”。添加操作进入主内容区的独立页面，不使用弹框。若扫描失败，保留重试按钮，并展示可复制的诊断摘要。

### 3.2 服务看板

桌面宽度优先使用表格；窄窗口退化为卡片。行内只放低风险操作：启用/禁用转发、刷新。删除转发和取消关注进入“更多”菜单并二次确认。

服务详情包含：

- 配置身份：类别、多个 TCP/UDP 绑定、进程路径或 WSL 发行版；
- 当前身份：PID、进程名、当前地址、最近发现时间；
- 转发：期望状态、系统实际规则、最近解析的 WSL IP；
- 诊断：错误码、可读说明和建议动作。

### 3.3 候选列表

候选数据只包含当前已绑定的端点：TCP `LISTENING` 和 UDP 绑定，不包含 TCP 已建立连接等非监听端口。界面直接按端口号提供可选项；同一运行环境中的同一端口，把不同地址和协议绑定合并为一项。界面默认筛选 TCP，用户可切换 UDP 或全部；类型不参与主排序，列表始终按端口号升序排列。候选项应明确显示：

- `TCP/UDP`；
- 地址和端口；
- Windows 进程名、PID、路径，或 WSL 发行版和进程名；
- “UDP 首版不可转发”等能力标记。

IPv4 的 `0.0.0.0:3000`、IPv6 的 `[::]:3000`，以及同号 UDP 绑定在发现层保留为独立记录，但在添加页和服务看板中合并为端口 3000。加入关注时一次保存该端口当前发现的全部绑定。

WSL 端口与 Windows `wslrelay.exe` 暴露的同号端口合并为一项，以 WSL 进程信息为主。PortProxy 由 IP Helper / `svchost.exe` 创建的监听端，如果其目标端口已被发现，则不作为独立服务候选；映射入口只作为目标端口的关系信息展示。

普通 Windows 端口显示标准端口的常见用途；无法可靠识别时只标记为应用监听或 Windows 系统服务，不猜测业务。绑定到通配地址或具体非回环地址的端口使用醒目的“对外监听”标记；该标记表示网络可达面扩大，不等价于已确认公网可达。

添加页默认隐藏由 `System`、`svchost.exe` 等 Windows 系统进程监听的端口，用户可通过“系统服务”筛选显式显示。候选和已关注服务的右键操作先打开上下文菜单；“打开进程目录”必须由用户再次点击，右键本身不执行外部操作。

## 4. 错误与确认

后端错误使用稳定错误码，前端负责本地化展示。至少包括：

- `CONFIG_INVALID`
- `DISCOVERY_FAILED`
- `CANDIDATE_STALE`
- `PORT_CONFLICT`
- `UNSUPPORTED_PROTOCOL`
- `ELEVATION_CANCELLED`
- `FORWARD_APPLY_FAILED`
- `FORWARD_VERIFY_FAILED`
- `ROLLBACK_FAILED`
- `WSL_UNAVAILABLE`
- `WSL_ADDRESS_UNAVAILABLE`
- `IP_HELPER_STOPPED`
- `IP_HELPER_CONTROL_FAILED`

确认框必须说清系统影响。例如“禁用转发会删除 Windows 端口代理规则，但不会停止业务服务，也不会删除关注项”。

## 5. 刷新策略

- 打开窗口后立即刷新；
- 首版不做后台周期扫描，避免反复创建系统查询进程；
- 用户点击刷新或完成增删改操作后更新运行快照；
- 转发变更后立即强制刷新；
- 同一时间只允许一个刷新任务，新的周期触发不叠加；
- WSL 扫描设置较短超时，单个发行版失败不阻断 Windows 结果。

前端保留上一次成功快照。部分扫描失败时展示数据陈旧标记和 warning，不把整个页面清空。
